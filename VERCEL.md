# Размещение на Vercel

Приложение продолжает исходный `main` 470b1a0. Vercel исполняет Python WSGI через `vercel_entry:app`, заданный в pyproject.toml. Формулы, проверка менеджером и интерфейс сохранены. Render/Neon для этого варианта не нужны. Пользователь открывает HTTPS-ссылку в браузере; исходные Excel и Python на его устройстве не требуются.

## Постоянная база

Vercel Function не является постоянным сервером с локальным диском. Для аккаунтов, сессий, импортированного набора и заказов нужна внешняя PostgreSQL. Для текущего размещения выбран Supabase Free, регион Frankfurt, и Vercel `fra1`.

Создать проект Supabase Free. Отключить Enable Data API и Automatically expose new tables: приложение обращается к PostgreSQL напрямую. Оно использует отдельную схему `seven_solutions`; не добавлять её к Exposed schemas. Для Vercel использовать строку Transaction pooler из Connect. Prepared statements отключены; TLS проверяет сертификат и имя сервера. При необходимости собственного CA задать PGSSLROOTCERT с путём к доверенному сертификату, не выключать проверку TLS.

Администрирование выполняется локально, не через публичный HTTP. Сохранить URL базы в игнорируемый `data/supabase-url.secret` (никогда не в чат/Git). В PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-cloud.txt
$env:PGSCHEMA='seven_solutions'
.\.venv\Scripts\python.exe cloud_admin.py --url-file data/supabase-url.secret migrate --source data/app.sqlite3
```

Миграция создаёт локальную резервную копию и переносит только в пустую схему, сохраняет пароли и владельцев заказов, проверяет все поля в транзакции. Сессии/временные расчёты не переносятся. Старые заказы без владельца остаются закрытым архивом. Для нового пустого пространства вместо миграции выполнить `init`, затем `create-user`; пароль вводится скрыто. Публичная регистрация закрыта.

## Конфигурация Vercel

- Framework Preset: Python, корень репозитория, конфигурация vercel.json и pyproject.toml.
- `DATABASE_URL`: секрет PostgreSQL только для нужного окружения, не для браузера.
- `PGSCHEMA=seven_solutions` (это также значение по умолчанию Vercel entrypoint).
- `APP_ORIGIN=https://точный-домен-проекта.vercel.app`. Если переменная отсутствует, используются VERCEL_PROJECT_PRODUCTION_URL, затем VERCEL_URL. Случайные Host/Origin отклоняются.
- `APP_ENV=cloud` устанавливается самим entrypoint. Отсутствие базы/HTTPS-конфигурации даёт 503, без временного SQLite fallback.

Можно импортировать разрешённый Git-репозиторий или использовать официальный Vercel CLI: `vercel link`, затем `vercel --prod`. Изменения исходников проходят ветку/PR. Не менять видимость репозитория и не включать платный план ради обхода ограничений Git-интеграции. `.vercelignore` исключает data/, .env*, базы, оригинальные Excel/ZIP и виртуальную среду. Не публиковать папку data через static hosting.

Hobby предназначен для личных некоммерческих проектов: демонстрация прототипа не означает, что тариф подходит для рабочей системы компании. Не включать Pro/платные ресурсы без отдельного решения владельца. Квоты бесплатного Supabase и Vercel контролируются в их кабинетах.

## Ограничение размера запросов

У Vercel лимит тела запроса/ответа — 4,5 МБ. Адаптер использует запас: не более 3 МБ на передаваемое тело. Большие JSON/ZIP браузер сжимает перед отправкой; распакованное тело ограничено 40 МБ, как в исходном приложении. Современный браузер нужен для CompressionStream. Расчёты передаются с HTTP gzip без изменения чисел. Не каждый ZIP можно сжать до лимита: в таком случае отображается понятная ошибка, следует загрузить нормализованный компактный JSON или перенести данные через локальную команду администрирования. Это не обход лимита Vercel.

Локально проверенные частные файлы: нормализованный JSON 38,6 МБ сжимается примерно до 1,4 МБ; сохранённый большой расчёт также сжимается примерно до 1,4 МБ. Это размер конкретного набора, не гарантия для любых будущих данных. Оригинальные файлы не входят в deploy.
