## Архитектура

- Локальный запуск не изменён: `python server.py`, SQLite, http://127.0.0.1:8765.
- Облачный запуск: Render Free → Gunicorn → `wsgi.create_app()` → те же маршруты и расчётный движок → PostgreSQL Neon Free. Стандартный HTTP-сервер не выставляется в интернет.
- `APP_ENV=cloud`, `DATABASE_URL` и точный HTTPS-origin обязательны. Render автоматически предоставляет `RENDER_EXTERNAL_HOSTNAME`; для собственного домена задать `APP_ORIGIN=https://example.com`. SQLite fallback в облаке запрещён.
- Публичная регистрация в облаке закрыта. Набор общий для допущенной команды; каждый участник может импортировать данные. Заказы и расчёты доступны только владельцу. Это одно закрытое командное пространство, не многоклиентский SaaS.
- Пароли сохраняются как PBKDF2-хеши. Cookie: HttpOnly, SameSite=Strict, Secure в облаке. CSRF, Host и Origin проверяются. PostgreSQL TLS проверяет сертификат и имя сервера через certifi.
- Вход в Render/GitHub/Neon и аккаунт приложения — разные учётные записи. Доступ к исходникам не даёт доступа к рабочей базе.

## Подключение Render

`render.yaml` описывает бесплатный веб-сервис из `main`, тесты перед сборкой, Gunicorn с одним worker и четырьмя потоками, `/healthz`. Автодеплой выключен: изменения проходят PR, затем владелец запускает Manual Deploy. Создание первого аккаунта выполняет `hosted_start.py`; shell на Render Free не нужен.

### Первый запуск с новой базой (через браузер)

1. Создать свои аккаунты [Render](https://dashboard.render.com/) и [Neon](https://console.neon.tech/). Выбрать бесплатные планы. Не добавлять платные диски, платную БД Render или автоматический переход на платный тариф.
2. В Neon создать проект на Free и базу в регионе, близком к Frankfurt. В окне Connect скопировать строку подключения PostgreSQL. Она содержит пароль: вставить её только в секрет `DATABASE_URL` в Render, не в GitHub или чат.
3. После ревью и слияния DEPLOY-2 открыть Render → New → Blueprint, подключить репозиторий `BAITC-Hacks/hack-2d79bdb0-7-solutions`, выбрать `main` и `render.yaml`. Для приватного репозитория администратор BAITC-Hacks должен разрешить GitHub App Render доступ: у Мадияра этот запрос ранее ожидал одобрения. Не делать коммерческий репозиторий публичным ради обхода разрешения.
4. Ввести три секрета: `DATABASE_URL`, `FIRST_USER_EMAIL` (логин приложения), `FIRST_USER_PASSWORD` (12–256 символов). Не использовать пароль GitHub/почты. Необязательный `FIRST_USER_NAME` задаёт имя, иначе используется «Администратор команды». Render сам задаёт HTTPS-домен. Проверить, что web service имеет план **Free**, и запустить создание.
5. После статуса Live открыть показанный Render адрес `https://…onrender.com`, войти заданными email/паролем. При старте создаются таблицы и один аккаунт, только если пользователей ещё нет. Если пользователи есть, их пароли не меняются. Удалить `FIRST_USER_PASSWORD`, `FIRST_USER_EMAIL` и `FIRST_USER_NAME` из Environment Render после успешного входа; повторный запуск работает без них. `DATABASE_URL` оставить.
6. Открыть «Демо-сценарии», рассчитать заказ, утвердить синтетическую позицию и скачать CSV. Демо встроено в код, реальные Excel для этой проверки не нужны.
7. Для работы с реальными данными войти и импортировать оба исходных ZIP через интерфейс либо нормализованный JSON (каждый запрос не более 40 МБ). Большой `data/dataset.json` с отступами сначала сохранить компактно командой ниже. Это общий набор команды; JSON заменяет весь набор. Исходные документы в репозиторий не загружать. Остальные устройства увидят тот же набор после входа; локальная SQLite автоматически с облаком не синхронизируется.

```sh
python -c "import json,pathlib; p=pathlib.Path('data'); (p/'dataset-cloud.json').write_text(json.dumps(json.loads((p/'dataset.json').read_text(encoding='utf-8')),ensure_ascii=False,separators=(',',':')),encoding='utf-8')"
```

Полученный `data/dataset-cloud.json` остаётся частным файлом; если он всё равно превышает 40 МБ, использовать ZIP по одному поставщику либо перенос базы ниже.

Для проверки PR до слияния создать Web Service вручную из `asanali/easy-deploy`, скопировать build/start команды и Environment из `render.yaml`, выбрать Python и Free. После слияния переключить ветку сервиса на `main`. Blueprint, в котором service.branch задан main, до слияния запустит старый код даже при выборе другой ветки самого Blueprint.

Если нужно сохранить существующие аккаунты и историю SQLite, сначала выполнить перенос ниже в **пустую** Neon, и только потом запускать веб-сервис. Первичная настройка аккаунта делает базу непустой: инструмент переноса справедливо откажется её перезаписывать. Старую базу не удалять.

### Проверка ссылки и сохранности

1. Открыть `/healthz`: ответ 200 означает, что сервер подключается к базе. В приватном окне `/api/status` без входа должен вернуть 401; публичной регистрации нет.
2. Войти, выполнить синтетический расчёт → утверждение → CSV. Зафиксировать номер заказа в «Мои заказы».
3. В Render выполнить Manual Deploy той же версии. После запуска снова войти: номер заказа и импортированный набор должны сохраниться.
4. Открыть HTTPS-ссылку с телефона через мобильный интернет. Войти тем же аккаунтом, проверить тот же заказ и экспорт. На телефоне не нужны Python, Git или исходные Excel.
5. Выдать другим участникам отдельные аккаунты через `cloud_admin.py create-user` (ниже). Набор общий, история заказа личная. Публичный URL сам по себе не даёт доступа к данным.

GitHub Pages не исполняет Python и PostgreSQL. Бесплатный Render засыпает при простое; первый запрос может ждать около минуты. Его файловая система временная, поэтому `data/` на Render не используется как рабочее хранилище. Neon Free имеет квоты (на момент проверки 0.5 GB/проект, 100 CU-hours/месяц, 5 GB исходящего трафика/месяц); контролировать расход и не включать платный план автоматически. База закрыта паролем и TLS, но это не private-network hosting.

## Перенос базы

Инструмент `cloud_admin.py` запускается локально, не является HTTP API. Установить `requirements-cloud.txt`. Использовать существующий URL PostgreSQL через переменную окружения `DATABASE_URL` или игнорируемый файл `data/neon-url.secret` с одной строкой URL. Файл не входит в архив кода и не передаётся Асанали. Для сервера используется переменная окружения, не локальный файл.

```sh
python -m pip install -r requirements-cloud.txt
python cloud_admin.py --url-file data/neon-url.secret migrate --source data/app.sqlite3
```

Перед выполнением прекратить изменения локальных данных: миграция — разовый снимок, не двусторонняя синхронизация. Команда создаёт согласованную копию SQLite и копии старых JSON в `data/backups/<UTC>/`, проверяет целостность, переносит пользователей, набор и заказы только в **пустую** PostgreSQL. В одной транзакции сравнивает все перенесённые поля; ошибка откатывает перенос. Повторный запуск на непустую базу прекращается без перезаписи. Сессии и временные расчёты не переносятся — войти заново. Исходная база не удаляется и не меняется.

На компьютере Мадияра при подготовке найдено 3 908 товаров, 1 аккаунт, 0 новых SQLite-заказов и 2 старых `order-*.json`. Пользователь явно выбрал **сохранить старые заказы только в закрытом архиве до уточнения владельца**. При будущем переносе они попадут в `documents.kind=legacy_order`, без владельца и без показа в личной истории. Не назначать их Мадияру автоматически.

Права новых членов команды добавляются владельцем базы через `python cloud_admin.py create-user` (DATABASE_URL в окружении); пароль вводится скрыто через getpass. Нет сброса пароля письмом, приглашений или ролей. После включения общего сервера использовать его как единственный источник актуальных данных; локальные SQLite между компьютерами не синхронизируются.
