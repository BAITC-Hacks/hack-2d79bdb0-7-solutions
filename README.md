# 7-Solutions — рекомендованные заказы

Локальный MVP для закупщика «Электрокомплект», HackAlem AI. Команда: Мадияр и Асанали.

Результат — таблица: **артикул, поставщик, рекомендуемое количество, обоснование, срочность**, с поиском, фильтрами и экспортом CSV. Приложение продолжает существующий Python + vanilla JavaScript проект.

## Запуск

Python 3.11+; единственная устанавливаемая зависимость — openpyxl (requirements.txt).

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

Откройте http://127.0.0.1:8765. На macOS/Linux используйте .venv/bin/python. Другой порт: `python server.py --port 8766`. Сервер слушает только localhost. Это не публичный многопользовательский сервис.

Без реальных файлов автоматически открывается синтетическое демо: 6 товаров, 4 положительные рекомендации. При стандартных параметрах DEMO-001 — 250 шт., DEMO-002 — 410 м. Демо явно отмечено и не смешивается с партнёрскими данными.

## Основной сценарий

1. Выберите данные партнёра или демо. При необходимости загрузите ZIP/нормализованный JSON.
2. Нажмите «Рассчитать». Параметры скрыты в раскрываемой панели.
3. Отфильтруйте поставщика и срочность, найдите артикул.
4. При настроенном API нажмите «Обоснования OpenAI» для текущей страницы (до 25 позиций).
5. «Экспорт CSV» выгружает **все позиции текущего фильтра**, а не только страницу. CSV содержит UTF-8 BOM, разделитель `;`, единицу учёта, режим demo/real и статус «Рекомендация». Поставщики сгруппированы.

Экспорт — предварительные рекомендации для решения менеджера, а не утверждение или отправка заказа. Старые API утверждения и его серверные ограничения сохранены, но исключены из упрощённого интерфейса. Предупреждения о качестве данных в интерфейсе не выводятся по запросу команды.

## OpenAI API

Необязательно. Скопируйте `.env.example` в `.env` и заполните `OPENAI_API_KEY`. Не перезаписывайте существующий .env. Можно вместо файла задать переменную окружения. `OPENAI_MODEL` по умолчанию `gpt-4o-mini`; можно указать доступную вашему проекту модель с Structured Outputs.

Используется [Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Запрос выполняется только по кнопке, с таймаутом 30 секунд и store=false. Ключ хранится на сервере и не передаётся браузеру. Дополнительный SDK не требуется: HTTPS через стандартную библиотеку Python.

Модель получает временный индекс и булевы признаки: риск дефицита, учтённые поступления, всплески, восстановленный спрос, рост и страховой запас. Артикулы, поставщики, названия, документы, реальные количества и Excel не отправляются. API формулирует короткое обоснование; не вычисляет количество и срочность. Числовая формула остаётся рядом. Тексты с цифрами, неполный ответ или некорректная структура отклоняются. Семантическая точность текста модели не гарантируется — менеджер может проверить его по формуле.

Успешные пояснения кешируются в текущем расчёте. При ошибке, отсутствии ключа или сети доступны исходные расчётные обоснования и экспорт. Ключ проверен живым вызовом на синтетической позиции; доступность API зависит от аккаунта, модели и лимитов. API-вызовы могут тарифицироваться.

## Данные и метод расчёта

Партнёрские источники: месячные продажи и остатки, динамика накладных, MOQ/кратность, поступления и сезонность. Соединение выполняется по поставщику и строковому коду 1С. ZIP читаются в памяти (до 40 МБ загрузки, до 150 МБ Excel). JSON заменяет набор; ZIP обновляет поставщика. Коммерческие файлы, локальные отчёты и заказы находятся вне Git.

```sh
python importer.py "Systeme electric.zip" "IEK.zip" --reconciliation-output data/reconciliation.json
```

- Положительные накладные используются для обнаружения всплесков через медиану и MAD. Повторные покупки клиента сохраняются при наличии customer_id. Очистка всплесков в HTTP-расчёте всегда включена, переключателя нет.
- База — последние шесть полных месяцев; учитываются сезонность товара/поставщика, рост, заданные дни stockout и страховой запас.
- Поступления учитываются по ETA в пределах горизонта. Срочно = ожидается дефицит до новой поставки; иначе положительная рекомендация плановая.
- Количество = max(0, спрос на горизонт + запас − остаток − поступления), с MOQ и округлением по кратности.
- Стандартные параметры: 23.09.2026, срок поставки 30 дней, период заказа 14 дней, страховой запас 14 дней. Это допущения, не договорные сроки.

Ограничения сохранены в расчётном ядре: неизвестный остаток предварительно считается нулём; месячный снимок не равен текущему свободному остатку. Не подтверждённые единицы и остатки блокируют старый API утверждения. Экспорт рекомендаций допускает предварительные позиции. Точных stockout и ID клиента в реальных выгрузках нет. Формат обмена с конкретной конфигурацией 1С не согласован. Точность прогноза, экономия и пилот с закупщиком не измерены.

Сверка DATA-1 доступна в `meta.reconciliation`: знаковые суммы динамики по коду/месяцу, разница с месячными продажами, пропуски и неполные периоды. Совпадение не доказывает одинаковый периметр источников; нормализованный JSON этой сверкой не проверяется. Реальные файлы локально импортированы: 3 908 товаров, 248 467 положительных строк накладных. Подробные расхождения хранятся только в data/.

## Структура и API

- engine.py — детерминированные количества, сезонность, рост, партии и ETA.
- importer.py — ZIP/Excel, нормализованный JSON, сверка.
- ai_explanations.py — необязательные обоснования OpenAI.
- server.py — localhost HTTP API, расчёты в памяти, экспорт и прежнее утверждение.
- static/ — дашборд без сборщика. demo.py — синтетические данные. tests/ — проверки.

GET /api/status выдаёт локальный токен и ai_configured. Все POST требуют X-App-Token.
POST /api/calculate: {demo, options}; /api/import: ZIP или JSON с X-Filename.
POST /api/explain: {calculation_id, ids}, до 25 позиций.
POST /api/recommendations/export: {calculation_id, ids} → CSV, без сохранения/утверждения заказа.
Сохраняются /api/approve, /api/export?id=... и /api/template. Перезапуск/импорт инвалидирует расчёты. Токен — защита локальной сессии, не многопользовательская авторизация.

## Проверки

```sh
python -m unittest discover -s tests -v
node --check static/app.js
```

35 тестов: расчётные инварианты, импорт и сверка, утверждение, CSV рекомендаций, обязательная очистка всплесков, OpenAI с подменённым транспортом, отсутствие ключа, таймауты и некорректные ответы. Тесты не требуют сети и API-ключа. Реальный API проверяется отдельно на демо.
