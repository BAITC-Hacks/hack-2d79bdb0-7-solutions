Репозиторий: https://github.com/BAITC-Hacks/hack-2d79bdb0-7-solutions
Последняя полная версия передачи: ветка `madiyar/cloud-deploy`. Она включает предыдущую `madiyar/dynamic-glass-plan-b` (PR #2, база 9ede0d6) и подготовку хостинга. Проверь актуальный статус веток/PR: если уже слиты, используй актуальный main. Не предполагай, что один main до слияния содержит все изменения.

Сначала:
1. Проверь git status, сохрани существующие незакоммиченные изменения. Сделай fetch; не используй reset --hard, force push и не затирай чужую работу.
2. Прочитай AGENTS.md → HANDOFF.md → README.md → DEPLOYMENT.md → DATA_CONTRACT.md → TASKS.md → CONTRIBUTING.md → DEMO.md из актуальной ветки.
3. Создай собственную ветку `asanali/<задача>` от полной актуальной версии. Не сливай PR без моей команды.
4. Установи requirements.txt, запусти `python -m unittest discover -s tests -v`, затем `python server.py`. Открой http://127.0.0.1:8765, создай локальный аккаунт и проверь демо. Ожидается 48 пройденных тестов и 1 пропущенный PostgreSQL-тест без TEST_DATABASE_URL. Он отдельно прошёл на настоящем Neon в изолированной временной схеме. Для JS: node --check static/app.js, static/scenario.js, static/auth.js.

Продукт: объяснимый расчёт заказов поставщикам для пополнения склада «Электрокомплект». Python + vanilla JS. Импорт Excel/ZIP/JSON, сезонность, рост, исключение разовых всплесков, компенсация только подтверждённых stockout, свободный остаток, ETA, MOQ/кратность, проверка менеджером и CSV. Коды — строки; неизвестный остаток не равен нулю; не выдумывать ID клиента, сроки, экономию и точность.

Сделано: фиолетовый Apple/Liquid Glass интерфейс с системными шрифтами и оригинальной иллюстрацией; сводка сверки DATA-1; «План Б» (задержка/рост спроса, дефицит и дополнительная срочная партия); SQLite, вход/регистрация локально, личная история заказов и серверная проверка владельца. Движок статистический, внешних AI API нет. Сценарии условные, не доказательство точности прогноза или экономии.

Файлы: engine.py — расчёт; importer.py — адаптеры и сверка; scenario.py — симуляция; server.py — маршруты/локальный запуск; storage.py — SQLite и PostgreSQL; wsgi.py — адаптер для Gunicorn; cloud_admin.py — офлайн-перенос и создание разрешённых пользователей; static/ — UI; tests/ — проверки.

Хостинг подготовлен, но НЕ запущен. Render Free + PostgreSQL Neon Free, render.yaml с автодеплоем ветки и тестами сборки. Публичная регистрация в облаке закрыта, HTTPS-origin и PostgreSQL обязательны, Secure cookie и TLS-проверка сертификата. Render ожидает разрешения администратора организации BAITC-Hacks на доступ к приватному репозиторию. Мадияр остановил размещение ради передачи: **сейчас не деплой и не переноси реальные данные**, пока мы не попросим возобновить. Автодеплой пока не включён и публичного URL нет.

Реальные данные остались у Мадияра: 3908 товаров, один локальный аккаунт, два старых JSON-заказа без владельца. Есть локальная резервная копия; в Neon рабочие данные не загружались. Старые заказы по явному решению Мадияра должны оставаться закрытым архивом до уточнения владельца. Не назначай их автоматически. Исходные ZIP и рабочие БД не находятся в Git; получи их у команды отдельно, либо продолжай с синтетическим demo.py. Не проси пароли/ключи в чат и не коммить data/, .env, *.secret, SQLite и коммерческие файлы.
