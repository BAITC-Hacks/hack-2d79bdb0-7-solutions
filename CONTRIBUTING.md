# Совместная работа Мадияра и Асанали

GitHub — общий источник исходников. Одинаковый репозиторий не означает общую папку в реальном времени: изменения становятся доступны другому участнику после коммита и push, а на его компьютере — после fetch/pull.

## Первый запуск

```sh
git clone https://github.com/BAITC-Hacks/hack-2d79bdb0-7-solutions.git
cd hack-2d79bdb0-7-solutions
python -m venv .venv
# Windows
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python server.py
```

На macOS/Linux активировать среду командой `source .venv/bin/activate`. Если Python называется `python3`, использовать его. Для демо исходные Excel не требуются.

## Каждая новая задача

Сначала проверить `git status`. Если есть свои изменения — сохранить их коммитом в своей ветке; не сбрасывать. Затем:

```sh
git switch main
git pull --ff-only origin main
git switch -c asanali/data-reconciliation
```

Название ветки менять под свою задачу. Мадияр использует, например, `madiyar/category-filter`. Отметить область работы в TASKS.md, выполнить задачу, проверить тесты, затем:

```sh
git add <конкретные-изменённые-файлы>
git commit -m "Describe the completed change"
git push -u origin asanali/data-reconciliation
```

Открыть Pull Request в main и передать второму участнику на просмотр. В PR кратко описать поведение, проверки и ограничения. Перед слиянием учитывать новые изменения main; конфликты разрешать по смыслу. Не использовать force push и не заменять общую историю.

## Передача между ИИ

Указать репозиторий, ветку, ID задачи, область файлов, результат и выполненные проверки. ИИ должен сначала прочитать AGENTS.md и HANDOFF.md, а не восстанавливать контекст по предположениям. После завершения обновлять документы реальным итогом, не обещаниями.

## Что не коммитить

Пароли, токены, .env, реальные коммерческие выгрузки, data/dataset.json, сохранённые заказы, кэши и .venv. Эти файлы исключены в .gitignore. Синтетическое демо версионируется в demo.py. Для одинаковых результатов на реальных данных оба участника должны использовать одинаковые исходные ZIP и параметры.
